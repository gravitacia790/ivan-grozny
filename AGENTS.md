# Правила работы над проектом «Исповедь Ивана Грозного»

## Границы задачи

- Основной проект находится в этой папке. Родительская папка содержит личные
  материалы и API.rtf; не включать её в репозиторий и архивы.
- Сайт предназначен для совместного урока истории и информатики, 7 класс.
- Сохранять оформление, вход, аудиовступление, чат, экспорт, сброс с
  подтверждением и адаптивность. Менять только то, что относится к запросу.
- Правила персонажа находятся в lib/instructions.ts. Это серверная инструкция,
  а не содержимое, редактируемое учеником. Читаемое описание — docs/agent-rules.md.
- Не ослаблять ограничения ради удобного теста или более эффектной демонстрации.
- Не помечать подборку учителя согласованной без явного согласования. Файл
  content/teacher-materials.md пока содержит заглушку, а не историческую базу.
- По прямому запросу пользователя исторические ответы разрешены по знаниям
  модели обо всей жизни и правлении Ивана IV. Подборка учителя необязательна;
  её отсутствие не должно блокировать ответы или показываться как ошибка.

## Как отвечать пользователю

- По-русски, кратко, по существу текущей задачи. Обычно 2–5 предложений.
- Сначала результат, затем существенное ограничение или необходимый следующий шаг.
- Не повторять план, не добавлять похвалу, рекламные формулировки и предложения
  «могу продолжить», если работа уже поручена.
- Не выдавать намерение за действие: различать подготовленные материалы,
  отправленное задание, успешный результат и проверенный результат.
- Не обещать видео с движением губ на основании статичного кадра и аудиофайла.
- Для платной генерации заранее проверить доступ аккаунта, стоимость и входы.
  Согласованная цена относится только к согласованной попытке; не запускать
  дополнительные платные попытки без разрешения.

## Секреты и сохранение

- Никогда не выводить содержимое API.rtf, ключи, env-секреты и заголовки авторизации.
- Не копировать ключ в исходники/public/Git/архив. Проверять только наличие и
  безопасный статус ответа; существующий запуск читает внешний файл в память.
- Не публиковать сайт и не отправлять в GitHub без соответствующего запроса.
- При просьбе зафиксировать состояние: проверить типы, API-контракт и сборку,
  записать фактические ограничения, сохранить исходники и локальную Git-версию.
- Не объявлять логические тесты проверкой живой модели; не выдавать ограниченный
  набор проверок за доказательство полной защиты от prompt injection.

# GigaChat — самостоятельные ответы

13 ноября 2026 года. По уточнённому запросу пользователя `AI_PROVIDER=gigachat`
вызывает только GigaChat: без поиска Яндекса/OpenAI и без их ключей.
Обычный ответ и итог урока формируются через GigaChat-3-Ultra — модель,
выбранную в кабинете пользователя. Температура 0.5, как в кабинете.

## Системный промпт

`lib/instructions.ts`: `gigachatInstructions`. Основа — предоставленный пользователем
текст: Иван Грозный, стилизованная лексика XVI века, сохранившиеся исторические
источники XVI–XVII веков, ответ до 1000 символов. Добавлены уточнения пользователя
об учебном уроке и возврате посторонних вопросов к жизни и правлению царя.
Сохранены запреты на выдуманные цитаты, оскорбления ученика и раскрытие настроек.
JSON-схема и сервер проверяют длину и формат. Для итогов урока остаётся отдельная
нейтральная инструкция, также передаваемая GigaChat.

В открытом проекте Studio поле «Системные инструкции» было пустым; исходная
инструкция находилась первым сообщением чата. Приложение явно передаёт её
адаптированную системную версию в каждом запросе API. Содержимое кабинета
не изменялось. Автоматической синхронизации промпта с кабинетом нет.

Внешний поиск отключён. Ответы основываются на знаниях модели, а не на
проверенных сервером публикациях. Модель не должна заявлять, что провела
поиск или сверила источники. Источники и подписанная библиография к новым
ответам GigaChat не создаются; запросы об источниках также получает GigaChat
с указанием не выдумывать список. Старые сохранённые ответы не переписываются.
Сохранённые режимы Яндекса/OpenAI продолжают работать по прежним правилам.

## Запуск

Двойной щелчок по `Запустить GigaChat.command` или:

```sh
AI_PROVIDER=gigachat python3 scripts/with-local-key.py dev
```

Внешний `../GigaChat API.txt` читается только в память процесса. В этом режиме
`API.rtf` не читается, запрос определения каталога Яндекса не выполняется.
На сервере задаётся секрет `GIGACHAT_CREDENTIALS`, необязательные настройки:
`GIGACHAT_SCOPE=GIGACHAT_API_PERS`, `GIGACHAT_MODEL=GigaChat-3-Ultra`.

Локальный официальный CA: `.local-certs/gigachat-ca.pem` (игнорируется Git).
Скрипт запуска задаёт NODE_EXTRA_CA_CERTS до запуска Node.js. Проверка TLS
включена; системное хранилище не изменялось. На другом компьютере CA
предоставляется отдельно, в сборку Cloud Functions он не включён.
Проверка OAuth и списка моделей без генерации: `python3 scripts/check-gigachat-access.py`.

## Варианты подключения и проверка

Выбран прямой TypeScript/REST в существующем сервере без новых зависимостей.
Также доступны официальные Python SDK (`pip install gigachat`) и JS/TS SDK
(`npm install gigachat`). [Документация SDK](https://developers.sber.ru/docs/ru/gigachat/guides/using-sdks),
[авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api),
[JSON-схема](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output),
[сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates).

Ранее живые OAuth и GET /models прошли из Python и Node.js. Живую генерацию
не запускали; качество ответов и соблюдение исторической основы не проверены.
Публичный сайт не переключён, публикация не выполнялась.

После отключения поиска прошли typecheck, test:api, test:yandex-function и
production build. Мок-тесты проверяют работу без ключей других провайдеров,
только OAuth/генерацию GigaChat, точную передачу серверного промпта, лимит
1000 символов, JSON-схему, итог урока, кеш токена и ошибки. Локальный сервер
перезапущен на http://127.0.0.1:3003; GET подтвердил
configured=true/provider=gigachat/sourceMode=model_knowledge/sourcesOnRequest=false.

# Локальное подключение Яндекса — 11 ноября 2026

Подключена Alice AI LLM (`aliceai-llm/latest`) через Responses API.
Публикация не выполнялась. OpenAI сохранён и остаётся провайдером по умолчанию
при прямом запуске Next.js без AI_PROVIDER.

## Запуск на этом Mac

```sh
python3 scripts/with-local-key.py dev
```

Скрипт читает внешний `../API.rtf` через textutil, извлекает по одному ключу
каждого провайдера в память. При наличии ключа Яндекса выбирает Яндекс,
если AI_PROVIDER явно не задан. Идентификатор каталога получает из списка
доступных моделей; если каталогов несколько, нужен явный YANDEX_FOLDER_ID.
Ключи и содержимое внешнего файла в проект не копируются.

Обратное переключение:

```sh
AI_PROVIDER=openai python3 scripts/with-local-key.py dev
```

Для сервера без внешнего файла задаются серверные переменные:
AI_PROVIDER=yandex, YANDEX_API_KEY, YANDEX_FOLDER_ID,
YANDEX_MODEL=aliceai-llm/latest. Не использовать префикс NEXT_PUBLIC для секретов.
Отдельная модель поиска задаётся через YANDEX_RESEARCH_MODEL.
Для стабильной подписи библиографии при смене ключей доступен SOURCE_RECEIPT_SECRET;
при его отсутствии используется прежний ключ OpenAI, затем ключ Яндекса.

## Адаптация и проверки

- Список разрешённых сайтов сохранён; для Яндекса разбит на группы до пяти доменов.
- Интернет-поиск обязателен, ссылки проверяются по разрешённым доменам,
  нужны минимум два разных учреждения/домена; JSON ответа проверяет сервер.
- Для аннотаций Яндекса допускается URL без схемы. При пустом названии
  показывается честная техническая подпись «Публикация на <домен>».
- Автоматические проверки покрывают OpenAI и Яндекс, включая заголовок доступа,
  разделение доменов, проверку формата, подписание и восстановление библиографии.
- Пройдены typecheck, test:api и production build.

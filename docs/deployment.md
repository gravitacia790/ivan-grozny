# Публикация сайта

Проект является отдельным репозиторием Next.js. В корне находятся package.json,
app/, content/, public/, Dockerfile и файл фиксации зависимостей package-lock.json.
API.rtf и личные документы из родительской папки в репозиторий не входят.

Репозиторий: https://github.com/gravitacia790/ivan-grozny (открытый).

## Опубликованная тестовая версия GitHub Pages

Адрес: https://gravitacia790.github.io/ivan-grozny/

Исходники находятся в ветке `main`, готовые статические файлы — в `gh-pages`.
GitHub Pages настроен на корень `gh-pages`; HTTPS включён.

Это тест интерфейса для коллег: главная страница, переходы, изображения и
42-секундная озвучка. ИИ-чат в этой публикации не подключён: статический
хостинг не запускает серверные маршруты. На сайте есть явное пояснение,
отправка вопросов отключена, ключ не включается в браузер или ветку публикации.
Обычный серверный режим в `main` сохранён для полноценного размещения.

Сборка для Pages: `npm run build:pages`. Результат — `.next-pages/`, включая
`.nojekyll`. Публиковать содержимое этой папки в `gh-pages`, сохраняя main
с исходниками. Сборка устанавливает basePath `/ivan-grozny` и отдельный режим
статического просмотра; серверный обработчик из `.ts` в неё не входит.

## Хостинг с поддержкой Next.js / Node.js

Подключить этот репозиторий к выбранному хостингу. Корневая папка приложения —
корень репозитория, Node.js 22.13 или новее.

- Установка: `npm ci`
- Сборка: `npm run build`
- Запуск: `npm start` (standalone-сервер слушает 0.0.0.0, порт берётся из PORT)

`npm run build` сам копирует в standalone изображения, аудио, статические файлы
и материалы учителя. Для локальной проверки production-сборки использовать
`npm run start:local` — этот режим слушает только 127.0.0.1.

Если платформа сама распознаёт Next.js, использовать её стандартный режим
Next.js, сохраняя серверные маршруты. Статический export включать нельзя:
чат требует `/api/chat`. GitHub Pages для полного сайта не подходит.

## Переменные окружения

Задать в настройках секретов хостинга, только для серверного процесса:

| Имя | Значение |
| --- | --- |
| OPENAI_API_KEY | Действующий ключ OpenAI; не добавлять в Git или Dockerfile. |
| OPENAI_MODEL | `gpt-4.1-mini`, если не выбран другой совместимый вариант. |
| TEACHER_MATERIALS_APPROVED | `false`, пока учитель не согласовал подборку. |
| PORT | Обычно задаётся платформой автоматически. |

Не использовать префикс NEXT_PUBLIC_ для ключа. Файл API.rtf на хостинг не нужен.
Материалы учителя находятся в `content/teacher-materials.md`; перед включением
содержательных исторических ответов заполнить подборку и согласовать её.

## Docker

Dockerfile собирает standalone-версию, копирует public, статические файлы Next.js
и серверные материалы. Ключ требуется при запуске, а не при сборке.

```sh
docker build -t ivan-grozny .
docker run --rm -p 3000:3000 --env-file .env.production ivan-grozny
```

`.env.production` — локальный неотслеживаемый файл с серверными переменными.
На платформе с Docker указать Dockerfile и порт 3000. Для HTTPS и домена
использовать настройки выбранного хостинга/обратного прокси.

## Проверки после размещения

Проверить главную страницу, картинку и воспроизведение `/media/intro-voice-v1.mp3`,
переход к чату и один контрольный вопрос. GET `/api/chat` показывает только
наличие серверного ключа и статус материалов. POST с сайта должен работать через
тот же домен. Reverse proxy должен сохранять HTTP Host, соответствующий домену
страницы, иначе защита Origin отклонит запрос.

Лимиты пока действуют на один процесс. Для нескольких экземпляров нужен общий
лимитер. На первом размещении использовать один экземпляр сервера.

Перед публикацией выполнить `npm run test:api` и `npm run build`.
Автоматическое размещение на хостинге пока не настраивалось.
Готового видео с движением губ пока нет; доступна аудиоверсия со статичным кадром.
